1. Explicação em 30 segundos

O projeto é um chat individual temporário. Uma pessoa cria uma sala, recebe um link ou QR Code e compartilha com outra pessoa. Cada participante escolhe seu idioma. A mensagem é enviada em tempo real e traduzida para o idioma de quem vai recebê-la. A conversa não é gravada.

Exemplo: uma pessoa escreve em português; ela continua vendo português, enquanto o parceiro recebe inglês ou espanhol, conforme sua escolha.

2. O carro completo: visão do sistema

Navegador → servidor Node.js → sala em memória → tradutor → navegador do parceiro
Parte visível
HTML, CSS e JavaScript formam telas, botões, formulários e mensagens.
Motor
Node.js executa o código do servidor e coordena as operações.
Câmbio em tempo real

Porta de serviço
Express recebe requisições HTTP e disponibiliza APIs.
Porta-malas permanente

GPS da tradução
LibreTranslate converte o texto entre idiomas.

3. Ferramentas: o que são e o que fazem

Node.js — o motor

É o ambiente que executa JavaScript no computador/servidor, sem depender do navegador. Neste projeto, inicia o servidor, acessa o banco, gerencia salas e conversa com o tradutor.

Express — o chassi e as estradas

É uma biblioteca para criar servidor web. Organiza endereços como /api/auth/login, recebe dados de formulários e entrega os arquivos do frontend.

Socket.IO — o rádio comunicador

Permite comunicação nos dois sentidos em tempo real. Eventos como enviar_mensagem, digitando e participante_saiu chegam sem recarregar a página. Também tenta reconectar se a internet oscilar.

HTML — a carroceria

Define a estrutura: campos, botões, cartões, tela da sala, login, cadastro e chat.

CSS — pintura e ergonomia

Define cores, espaçamentos, tamanhos, responsividade e adaptação para celular.

JavaScript do navegador — painel do motorista

Reage aos cliques, valida campos, abre o Socket.IO, envia mensagens e atualiza a tela quando chega uma resposta.

SQLite — gaveta de documentos

É um banco leve guardado em arquivo. Salva contas, e-mails, hashes das senhas, idiomas, favoritos e tokens de redefinição. Não salva o histórico do chat.

bcryptjs — cofre das senhas

Transforma a senha em um hash. O sistema compara a senha informada com o hash, sem guardar a senha original.

express-session — pulseira de identificação

Usa uma sessão para lembrar que um usuário fez login. Assim, as rotas de amigos podem permitir ou negar acesso.

LibreTranslate — tradutor principal

É executado localmente com Docker e traduz português, inglês e espanhol. Se estiver indisponível, o projeto tenta alternativas e, no pior caso, entrega o original com um aviso.

Docker Compose — caixa isolada

Inicia o LibreTranslate em um container, uma espécie de ambiente separado que facilita instalar e executar o serviço.

Nodemailer — serviço de correio

Envia o e-mail com o link para redefinir senha.

QR Code — convite visual

Transforma o link da sala em um código que o celular consegue ler com a câmera.

5. Funcionamento passo a passo

5.1 Criar sala

  1. O usuário informa nome e idioma.
  2. O navegador emite criar_sala.
  3. O servidor cria um UUID, como um número de chassi único.
  4. A sala fica em um Map na memória.
  5. O sistema gera link e QR Code.

5.2 Entrar pelo convite

  1. O convidado abre o link.
  2. A página consulta se a sala existe.
  3. Ele informa nome e idioma.
  4. O servidor associa seu socket à sala.
  5. O estado muda de aguardando para ativo.

5.3 Enviar mensagem

  1. O texto sai do navegador pelo Socket.IO.
  2. O servidor aplica limite de frequência e tamanho.
  3. O remetente recebe a versão original.
  4. O texto é enviado ao tradutor com origem e destino.
  5. O parceiro recebe a tradução.

5.4 Sair ou desconectar

O botão “Sair da Sala” encerra imediatamente. Em uma queda temporária, o servidor aguarda até 120 segundos para uma reconexão. Depois, remove a sala da memória.

6. Códigos principais, traduzidos para linguagem simples

6.1 Ligando o servidor — backend/server.js

const app = express();
const server = http.createServer(app);
const io = new Server(server);

app.use(express.json());
app.use(express.static(frontendDir));

server.listen(PORT, () => {
  console.log('Servidor iniciado');
});

Leitura: cria o servidor, permite receber JSON, disponibiliza o frontend e abre uma porta para os navegadores se conectarem.

6.2 Criando uma sala

const salaId = uuidv4();
const sala = {
  id: salaId,
  status: 'aguardando',
  criador: { socketId: socket.id, nome, idioma },
  convidado: null
};

this.salas.set(salaId, sala);
socket.join(salaId);

Leitura: cria uma identidade única, registra o criador, deixa a vaga do convidado livre e coloca o socket na sala.

6.3 Enviando e traduzindo

const traducao = await traduzirTexto(
  texto,
  remetente.idioma,
  destinatario.idioma
);

socket.emit('mensagem_recebida', {
  lado: 'me', texto: textoOriginal
});

io.to(destinatario.socketId).emit('mensagem_recebida', {
  lado: 'other', texto: traducao.texto
});

Leitura: a mensagem original vai para quem escreveu; uma cópia traduzida vai para o parceiro. Esse é o coração do projeto.

6.4 Escolhendo o idioma

if (src === tgt) {
  return { texto, traduzido: false };
}

fetch('/translate', {
  method: 'POST',
  body: JSON.stringify({
    q: texto, source: src, target: tgt
  })
});

Leitura: se os dois idiomas forem iguais, economiza uma chamada. Se forem diferentes, envia o texto e os idiomas para o tradutor.

6.5 Salvando usuário com segurança

const senhaHash = await bcrypt.hash(senha, 10);
db.criarUsuario.run(
  id, nick, email, senhaHash, idioma, '[]'
);

Leitura: a senha é transformada antes de ser salva. Se alguém visse o banco, não encontraria a senha original.

6.6 Evitando código malicioso

function escaparHTML(texto) {
  return texto
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;');
}

Leitura: símbolos que poderiam virar HTML ou JavaScript são convertidos em texto. Assim, uma mensagem não executa um script no navegador.

6.7 Reconexão automática

const socket = io('/', {
  reconnection: true,
  reconnectionAttempts: 10,
  timeout: 10000
});

Leitura: o navegador tenta reabrir a comunicação se houver uma queda breve.

7. Segurança e qualidade

  • Senhas protegidas com bcrypt.
  • Consultas preparadas no SQLite.
  • Validação de nome, e-mail, idioma e tamanho da mensagem.
  • Limite de uma mensagem a cada 500 ms.
  • Escape de HTML contra XSS.
  • Tokens de recuperação expiram em uma hora.
  • Fallback de tradução mantém a conversa funcionando.
  • Testes verificam banco, tradução, QR Code, salas e autenticação.
Explicação honesta: a solução está adequada para a feira e demonstra os conceitos. Para produção em grande escala, seriam necessários HTTPS obrigatório, CORS restrito, armazenamento de sessão externo, proteção contra CSRF, limite de tentativas de login e monitoramento.

8. Perguntas prováveis da banca

As mensagens são armazenadas?
Não. Elas são transmitidas em tempo real. A sala fica na memória e é apagada ao terminar.

Por que usar Socket.IO?
Porque o chat precisa trocar dados imediatamente, sem recarregar a página.

E se a tradução falhar?
O sistema tenta alternativas. Se todas falharem, mostra a mensagem original e um aviso.

O convidado precisa se cadastrar?
Não. O cadastro é opcional; ele pode entrar apenas com nome e idioma.

O que fica no banco?
Usuários, senhas protegidas, idiomas, favoritos e tokens de reset. O histórico do chat não fica.

Qual é a ideia principal?
Permitir que duas pessoas conversem mesmo sem dominar o mesmo idioma.
