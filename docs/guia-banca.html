Chat com Tradução Simultânea

FECIP 2026

Explicação simples para apresentar aos professores

“Entra, conversa, traduz, tchau.”

1. O que é o projeto?

É um site de conversa entre duas pessoas que podem falar idiomas diferentes. Uma pessoa cria uma sala e envia um link ou QR Code para outra. Cada uma escolhe o idioma que entende melhor.

Quando alguém escreve, o sistema mostra a mensagem original para quem enviou e manda uma tradução para o outro participante.

Exemplo: eu escrevo “Bom dia” em português. Eu continuo vendo “Bom dia”. Se a outra pessoa escolheu inglês, ela recebe “Good morning”.

A sala é temporária. As mensagens não são gravadas. Quando a conversa termina, o histórico desaparece.

2. O projeto explicado como um carro

Para entender melhor, imagine que o sistema é um carro. Cada ferramenta é uma peça diferente:

HTML é a carroceria.
Cria as telas, botões, campos e a área onde aparecem as mensagens.
CSS é a pintura e o acabamento.
Cuida das cores, tamanhos, organização e adaptação para celular.
JavaScript é o painel de comandos.
Percebe cliques, textos e respostas, e faz a página reagir.
Node.js é o motor.
Executa o programa no servidor e coordena as outras peças.
Express são as estradas.
Leva cada pedido ao lugar certo: login, cadastro, sala e tradução.
Socket.IO é o rádio.
Leva mensagens entre os dois participantes na mesma hora, sem atualizar a página.
SQLite é a gaveta de documentos.
Guarda contas, e-mails, senhas protegidas e favoritos.
LibreTranslate é o intérprete.
Traduz uma mensagem de um idioma para outro.
Docker é a caixa do intérprete.
Ajuda a instalar e executar o LibreTranslate separadamente.

3. O que cada ferramenta faz

Node.js

Executa o código do servidor. Ele cria o sistema, controla as salas, acessa o banco e chama o tradutor.

Express

Ajuda a criar o servidor web. Organiza endereços como /api/auth/login e /api/salas.

Socket.IO

Faz a comunicação em tempo real. É o responsável por enviar mensagens, avisar que alguém está digitando e informar quando alguém saiu.

SQLite

É um banco de dados simples que fica em um arquivo. Guarda os usuários, mas não guarda o histórico das conversas.

bcryptjs

Protege as senhas. O sistema não salva a senha original; salva uma versão codificada dela.

express-session

Lembra que o usuário fez login e permite controlar o acesso à lista de amigos.

LibreTranslate

Faz a tradução automática entre português, inglês e espanhol. Se falhar, o sistema tenta alternativas e avisa o usuário.

Nodemailer

Envia o e-mail usado para recuperar uma senha esquecida.

QR Code

Transforma o endereço da sala em uma imagem que pode ser lida pela câmera do celular.

4. O caminho de uma mensagem

  1. A pessoa escreve no navegador.
  2. O navegador envia o texto pelo Socket.IO.
  3. O servidor verifica se ela está em uma sala.
  4. O sistema limita o tamanho e a frequência das mensagens.
  5. O remetente recebe o texto original.
  6. O servidor verifica o idioma do parceiro.
  7. Se necessário, chama o LibreTranslate.
  8. O parceiro recebe a tradução.

5. Como a sala funciona

Criação: o usuário informa nome e idioma. O servidor cria um código único, um link e um QR Code.

Entrada: o convidado abre o link, informa nome, escolhe idioma e entra.

Conversa: os dois trocam mensagens e podem ver quando o outro está digitando.

Saída: ao clicar em “Sair da Sala”, a conversa termina. Se a internet cair, o sistema espera até dois minutos para uma reconexão.

7. Trechos principais, explicados

Ligando o servidor

const app = express();
const server = http.createServer(app);
const io = new Server(server);

app.use(express.json());
app.use(express.static(frontendDir));
server.listen(PORT);

Esse código cria o servidor, permite receber informações, mostra as páginas e abre a porta para os usuários.

Criando uma sala

const salaId = uuidv4();
const sala = {
  id: salaId,
  status: 'aguardando',
  criador: { nome, idioma },
  convidado: null
};
salas.set(salaId, sala);

O sistema cria um número único para a sala, registra o criador e deixa espaço para o convidado.

Enviando a mensagem

socket.emit('mensagem_recebida', {
  lado: 'me',
  texto: textoOriginal
});

io.to(destinatario.socketId).emit('mensagem_recebida', {
  lado: 'other',
  texto: textoTraduzido
});

O primeiro comando mostra o original para quem escreveu. O segundo entrega a tradução ao parceiro.

Protegendo a senha

const senhaProtegida = await bcrypt.hash(senha, 10);
salvarUsuario(nick, email, senhaProtegida);

A senha é protegida antes de ir para o banco. A senha verdadeira não fica armazenada.

Protegendo as mensagens

function escaparHTML(texto) {
  return texto
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;');
}

Isso impede que alguém envie código escondido em uma mensagem para tentar executar algo no navegador.

8. Segurança

  • Senhas protegidas.
  • Consultas preparadas no banco.
  • Limite de tamanho e velocidade das mensagens.
  • Tratamento de caracteres perigosos.
  • Links de recuperação que expiram.
  • Reconexão quando a internet oscila.
Explicação honesta: o projeto está preparado para a demonstração. Para uma empresa com muitos usuários, ainda seriam necessários HTTPS obrigatório, controles mais rígidos e monitoramento.

9. Respostas para a banca

As mensagens ficam salvas? Não. Elas são transmitidas e mostradas na hora.

O convidado precisa de cadastro? Não. O cadastro é opcional.

O que acontece se o tradutor falhar? O sistema tenta alternativas. Se todas falharem, mostra o original e um aviso.

Por que usar Socket.IO? Para entregar mensagens imediatamente, sem recarregar a página.

Qual é a principal finalidade? Ajudar duas pessoas a conversar mesmo sem falar o mesmo idioma.
